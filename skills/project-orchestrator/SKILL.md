# 项目主控、协作与交接

让主控角色持续存在，让承载角色的对话可以更换。项目文件和可复核产物负责保存连续性，不把对话摘要当成已验证事实。

## 接手项目

1. 确认项目根目录，读取适用的 AGENTS.md、用户本次目标和已有进度入口。优先沿用项目既有任务系统、文档路径和格式，不另建平行账本。
2. 核对当前分支、未提交修改、最近相关提交以及尚在运行的任务。保护用户和其他代理的修改；状态文件与实际产物冲突时记录差异再判断，不自动覆盖。
3. 从记录中区分：已验证事实、当前决定、待验证假设。只有缺失信息影响当前行动时才询问用户。
4. 明确本轮结果与验收条件。探索期先验证核心假设和最小端到端流程，边界稳定后再增加并行度。

## 按需调度

- 当前主控负责目标、依赖、任务边界、结果验收及后续调度；子代理只接收完成其任务所需的上下文。
- 仅在可用工具及授权允许时调用子代理。读取实际并发限制，不把某个会话的配额写成通用限制。无子代理工具时采用同样的任务记录顺序执行，并如实说明。
- 独立调查、评审和边界清楚的模块适合并行；串行依赖、接口未定或同文件密集修改适合顺序完成。不要为了使用多代理而拆碎小任务。
- 每次分派给出任务 ID、目标、必要背景、输入、允许修改的范围、依赖、验收条件、回报要求。要求执行代理说明相关约束和权限不足，不让它从任务描述中推断额外授权。
- 分配不重叠的文件责任；共享文件由指定负责人整合。使用隔离工作区须符合用户要求和工具权限，记录分支、工作区与整合方式。不要默认创建 worktree。
- 优先使用子代理机制完成内部委派。独立可见聊天是另一种工作模式，只有用户明确要求或授权时才创建并发送任务；不要把子代理冒充侧栏项目聊天。

## 验收并保存进度

子代理回报应包含：完成内容、产物/文件或提交、执行的验证及结果、未完成项、风险和阻塞。主控针对关键结论检查原始产物与相关验证，避免仅复述“已完成”。同源代理的一致意见不等于独立证据。

在阶段完成、决定改变、任务阻塞或准备交接时更新检查点。无需逐次工具调用写日志。按项目约定记录；无既有约定时，采用以下最小集合：

- `docs/STATUS.md`：当前目标与验收标准、任务状态与负责人、已验证结果、阻塞及下一步。
- `docs/DECISIONS.md`：影响后续工作的决定、原因、限制和待验证假设；有实质决定时才创建。
- `docs/HANDOFF.md`：准备交接时创建，保留足够恢复工作的信息和证据链接。

具体字段与项目规则片段见 [检查点和交接约定](references/checkpoints.md)，仅在初始化或交接时读取。记录使用项目时区和可区分的检查点标识。将“未执行”“未验证”“执行失败”和“通过”分开写。

保持入口短小，把历史详情留在已有任务、提交及证据中。按需读取，不在每个新对话中载入全部历史。主控协调任务状态，执行代理汇报自己的结果，避免竞争覆盖同一状态文件。不得把密码、Token、私钥或私人环境材料放入可发布技能或交接摘要。

## 持久化项目规则

用户要求项目以后沿用此流程时，先检查并合并现有 AGENTS.md，只增加启动恢复、委派边界、检查点更新和交接规则。不要替换整个文件，也不要把当前任务细节塞入长期指令。

明确区分“技能已安装”“项目规则已写入”“项目状态已保存”。安装技能本身不代表所有项目已启用，也不代表打开项目就会自动执行。

## 更换主控对话

适合交接的时机是完成一个阶段、目标发生明显切换或长历史已影响工作。不要频繁轮换尚未落地的复杂调查。

1. 停止派发新工作，将现有任务完成、暂停于明确检查点，或记录仍运行的任务 ID、位置、状态及待处理结果。不要把当前子代理句柄当成新对话一定能继续控制的资源。
2. 保存状态和交接记录，包含工作区、分支/提交、未提交修改、已验证结果、约束、未解决问题及可直接执行的下一步。不要为了交接擅自提交或推送。
3. 用户已授权创建后继聊天且工具可用时，在同一项目建立全新对话；发送简短任务和交接文件位置。只有工具返回真实 ID 后才记录新主控。新建失败时保留旧主控，不反复创建重复聊天。
4. 接手方读取项目指令及检查点，核对真实工作区并确认接管。状态中的主控记录只是协作约定，不是跨进程锁；确保只有一个主控继续派发写任务。
5. 创建/发送成功不等于接管成功。能够等待或读取接手结果时验证接管，之后旧主控停止派发。无法观察时标记“接管待确认”，明确当前停留点；不要声称已无缝接续或自动归档旧聊天。
6. 没有新建聊天能力或授权时，交付可直接复制的启动提示词和检查点路径，让用户在新对话继续。保留已完成的文件工作。

新对话提示词引用交接文件并给出目标和验收条件。Fork 保留历史，不能作为清空上下文的方案；名为 handoff 的工具可能只迁移执行位置或 Git 状态，使用前检查其真实语义。

## 上下文与自动化边界

不要猜测精确 token 占用或承诺固定百分比自动换对话。默认采用阶段检查点。

若用户要求严格阈值自动交接，先核实当前运行时是否提供可靠的上下文用量、生命周期事件、创建聊天及接管观测能力。自动压缩阈值只控制压缩，不等于轮换聊天；Hook 也不天然具备可靠总结或转移主控能力。缺少组件时说明缺口，不能用无限轮询或定时自动化冒充事件交接。

实现自动轮换必须在用户授权范围内，具备幂等检查点、重复创建防护、单一主控转移、失败回退和有界重试，并实际验证一个完整交接周期。已有项目约定不扩大部署、外部通信或其他敏感操作权限。
