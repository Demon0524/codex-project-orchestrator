# 检查点和交接约定

这些是项目没有既有约定时可采用的模板。只填写与当前工作有关的字段，不建立空白文档体系，不复制全部聊天。

## STATUS.md 的最小内容

- 更新日期、时区及检查点 ID。
- 当前目标、范围、验收标准。
- 当前主控标识（仅使用已知真实标识，未知则写未记录）。
- 任务表：任务 ID、目标、负责人、状态、依赖、产物、验证结果。
- 影响下一步的已知事实、阻塞、待验证假设。
- 下一步行动及触发条件。

任务状态可用 planned / running / blocked / ready-for-review / done。收到回报先进入待验收，验收通过再记完成；按项目既有状态体系调整。

## HANDOFF.md 的恢复内容

- 来源主控、接手主控及状态：prepared / takeover-pending / accepted。未知标识不编造。
- 检查点 ID、时间、目标和验收条件。
- 项目根目录、相关工作区、分支、基准提交。
- 未提交修改的范围和归属；不能安全提交的原因（如有）。
- 已完成及已验证内容，指向具体文件、提交、任务或测试证据。
- 未执行和失败的验证、尚未解决的问题。
- 当前有效的关键约束和决定，引用项目指令及决策记录。
- 仍在运行的任务及真实标识、结果获取方式；新会话无法控制的资源要明确注明。
- 下一项可执行行动、依赖和完成条件。
- 接管确认结果；尚未观察时保持 takeover-pending。

交接摘要应足够让新代理判断下一步，同时保留深入核验的入口。旧记录不是现网实测。

## 可合并到 AGENTS.md 的规则片段

根据已有章节调整措辞，不覆盖原文件：

```markdown
## 项目主控与接续

- 接手时先读取项目状态和最新交接记录，核对实际工作区、未提交修改及运行任务。
- 主控负责拆解、按需调度子代理、验收与整合；每个执行任务明确产物、修改边界和完成标准。
- 并行任务划分文件责任；共享文件由指定负责人整合。工具、并发数和工作区方式以当前环境及授权为准。
- 阶段完成、关键决定变化或阻塞时更新项目状态，区分事实、决定、假设及验证结果。
- 更换主控前保存交接记录；接手者核验并确认后，由其继续派发任务。
- 使用 project-orchestrator 技能（若可用）细化上述流程；技能不可用时仍遵循本项目规则。
```

具体文件路径应替换为项目实际入口。创建独立后继聊天及跨聊天发送消息仍须符合用户授权和当前工具要求；此片段不是额外授权。

## 新主控启动提示词

```text
接手当前项目的主控工作。先读取适用的 AGENTS.md、项目状态及最新交接记录，核对分支、未提交修改与运行任务，再确认接管。
本轮目标：[具体结果]
验收条件：[可验证标准]
沿用已记录的有效约束，按需分派子代理并维护进度。不要从旧摘要推断已经通过的验证或额外操作权限。
```
